## [1.0.30] - 2026-08-30

### Android Client API on Smart-Sync Port
- **Расширение REST API на порту Smart-Sync (18089)**:
  - Выведен полный набор эндпоинтов галереи для создания полноценного мобильного клиента Android с единой авторизацией по токену (`X-Sync-Token`, `Authorization: Bearer`, либо URL query `?token=...` для библиотек Glide/Coil):

    - `GET /api/v1/albums` — список альбомов с обложками и счетчиками фото;

## [1.0.20] - 2026-08-28

### Zero-Copy Progressive Full Photo Streaming in Lightbox
- **Устранение OOM-падений и перезагрузок при просмотре полноэкранных фото**:
  - **Zero-Copy Streaming**: в Lightbox полноразмерное фото теперь читается браузером напрямую через HTTP-стриминг файла (`/api/photos/{id}/file`), передавая декодирование аппаратному GPU смартфона/ПК. Роутер расходует **0 МБ Go RAM и 0% CPU**.
  - **Мгновенный Low-Res превью**: при перелистывании фото сначала отображается уже готовая маленькая миниатюра из кэша (0 мс), затем плавно обновляется на кристально четкий полноразмерный снимок.
  - **Оптимизация порядка поворота (`thumbnail.go`)**: масштабирование картинки теперь выполняется **ДО** поворота. Вместо поворота 48 млн пикселей (192 МБ RAM) поворачивается готовая крошечная миниатюра 320x240 (0.05 МБ RAM) — снижая расход памяти в 300 раз.

## [1.0.19] - 2026-08-28

### Embedded EXIF Thumbnail Fast-Path & Strict Viewport Lazy Loading
- **Мгновенное извлечение встроенных миниатюр EXIF (`ExtractEmbeddedThumbnail`)**:
  - При запросе сетки фото сервис читает готовые JPEG-миниатюры прямо из заголовков EXIF (IFD1). Для 90% фото с камер и смартфонов генерация занимает **0.001 секунды при 0% CPU и 0 МБ RAM**.
- **Строгий `IntersectionObserver` с `data-src` на клиенте**:
  - Браузер запрашивает миниатюры **исключительно для карточек, реально видимых на экране** (`rootMargin: '100px'`). Фоновые и непрокрученные карточки больше не создают лишней нагрузки на роутер.
- **Ограничение параллелизма (`max_concurrent_workers: 1`)**:
  - Строго последовательная генерация миниатюр предотвращает параллельные пики памяти и оставляет ядро CPU свободным для сети роутера.
- **Мгновенное освобождение памяти после масштабирования (`debug.FreeOSMemory`)**.

## [1.0.18] - 2026-08-28

### Strict <80MB Memory Budget & Zero-Allocation Timeline
- **Жесткий лимит памяти и устранение всплесков RAM**:
  - **`debug.SetMemoryLimit(80MB)` & `debug.SetGCPercent(20)`**: Go Runtime жестко удерживает использование памяти в рамках 80 МБ.
  - **Zero-Allocation Timeline**: прокрутка и пагинация фотоленты по умолчанию теперь читаются напрямую срезом из предсортированного массива, исключая создание промежуточных 80k-массивов при каждом HTTP-запросе.
  - **Кэширование статистики и альбомов**: `GetTimelineSummary`, `GetAlbums` и `GetStats` больше не обходят 80k фото при каждом тике SSE/запросе, а мгновенно возвращают предвычисленные структуры.
  - **Очистка `FullPath` в памяти**: устранено хранение избыточных абсолютных путей в оперативной памяти (пути генерируются на лету).
