# Changelog

All notable changes to the SmartRoute project will be documented in this file.

## [1.0.184] - 2026-09-26 - Устранение циклических перегрузок CPU, чтение startup-config в KeeneticOS и исправление классификации маршрутов
- **Устранение периодических перегрузок CPU и спама командами NDM (`internal/routing/manager.go`)**:
  - Из 60-секундного тикера `cleanupExpired()` полностью удален тяжелый вызов `BatchAddRoutes(allRoutes)`, циклически передобавлявший тысячи маршрутов каждую минуту. Теперь при истечении TTL маршруты удаляются из NDM строго точечно (`m.ndm.DeleteRoute(ip, ifaces)`).
  - Алгоритм агрегации суперсетей `sweepAndAggregateSupernets()` оптимизирован с $O(N^2)$ (свыше 36M операций под RWMutex) до быстрого $O(N)$ через префиксное группирование по `/24` корзинам интерфейсов, снижая нагрузку на CPU роутера до 0%.
- **Надежное чтение конфигурации KeeneticOS 4.x/3.x (`internal/routing/keenetic_ndm.go`)**:
  - Реализован метод `readRunningConfig`: первоочередное чтение через нативную команду `more startup-config` (выполняется за < 0.5с с полными комментариями `! SR:`), устраняя ошибку `Core::FileSystem::Base error: failed to open "running-config"`.
  - В `BatchAddRoutes` внедрен предохранитель `batchMu.TryLock()` и строгая проверка результата чтения конфигурации: при сбое чтения процесс немедленно прерывается без ошибочного затирания или слепого дублирования маршрутов.
- **Исправление классификации туннельных маршрутов и фильтра «Системные / WAN» (`internal/routing/keenetic_ndm.go`)**:
  - Маршруты через туннельные интерфейсы (`OpkgTun*`, `Wireguard*`, `nwg*`, `tun*`, `OpenVPN*`, `SSTP*`) больше никогда не классифицируются как системные WAN-маршруты при временном отсутствии комментариев — они корректно определяются как `smart_route` либо `orphan` (осиротевшие).
  - В категории «Системные / WAN» отображаются исключительно реальные физические шлюзы и локальные сегменты роутера (Home, Guest, Bridge, ISP).

## [1.0.183] - 2026-09-25 - Строгий белый список DNS-модификаторов и исключение ложных блокировок в списках AdGuard
- **Строгая изоляция DNS-модификаторов (`internal/dns/blocklist.go`)**:
  - Реализован строгий валидатор `isDNSModifier`: на уровне DNS-блокировок разрешены исключительно профильные директивы (`important`, `badfilter`, `dnstype=`, `dnsrewrite=`, `client=`, `ctag=`).
  - Все браузерные и контекстные HTTP-модификаторы AdGuard (включая `$referrerpolicy=origin`, `$removeheader=...`, `$jsonprune=...`, `$replace=...`, `$cookie=...`, `$csp=...`, `$permissions=...` и любые будущие расширения синтаксиса браузерных блокировщиков) теперь гарантированно отсеиваются и не приводят к полному блокированию доменов в DNS.
  - Устранены ложные блокировки легитимных ресурсов, содержавшихся в расширенных списках AdGuard Annoyances/Russian: `laposte.net`, `shiftdelete.net`, `abinbevefes.ru`, `olympiapark.de`, `ertflix.gr`, `destyy.com`, `gestyy.com`.
- **Фильтрация процедурных косметических правил и IP-адресов (`internal/dns/blocklist.go`)**:
  - В `ParseFilterRuleBytes` добавлен пропуск процедурных косметических правил AdGuard (`#$?#` и `#@$?#`).
  - В `cleanDomainBytes` добавлено отсечение сырых IPv4/IPv6 адресов (`$network`), предотвращающее загрязнение карты доменных хэшей.
- **Расширение модульных тестов (`internal/dns/dns_test.go`)**:
  - Добавлены тесты для проверки корректного пропуска `$referrerpolicy`, `$removeheader`, `#$?#`, прямых IP-адресов и сохранения функционала `$important` (`||deloton.com$important`, `||adsrvmedia.adk2.co^$important`).

## [1.0.182] - 2026-09-25 - Фильтрация браузерных модификаторов и скриптлетов в правилах DNS (разблокировка Reddit)
- **Исключение браузерных модификаторов и параметров URL (`internal/dns/blocklist.go`)**:
  - В `hasBrowserOnlyModifiers` добавлена поддержка модификаторов очистки параметров запросов (`$removeparam`, `$removeparam=...`), `cookie`, `csp`, `header`, `permissions`, `stealth`, а также инвертированных модификаторов (через `strings.TrimPrefix(p, "~")`).
  - Устранено ложное блокирование `reddit.com` и его поддоменов (`www.reddit.com`), возникавшее из-за правила очистки URL из AdGuard Annoyances (`||reddit.com^$removeparam=recap_redirect`), которое ошибочно урезалось до доменного блокирования `0.0.0.0`.
- **Фильтрация косметических и скриптлетных правил AdGuard (`internal/dns/blocklist.go`)**:
  - В `ParseFilterRuleBytes` добавлен пропуск инъекций скриптлетов (`#%#`, `#@%#`) и правил внедрения CSS (`#$#`, `#@$#`, `$@$`).
  - В `cleanDomainBytes` добавлена строгая проверка RFC 1035 / RFC 1123 через `bytes.ContainsAny(d, " /*:?#=&%+,!@;\"'()<>\\")`, гарантирующая отсечение правил путей URL (например, `||domain.com/path/*`) и недопустимых символов.
- **Расширение модульных тестов (`internal/dns/dns_test.go`)**:
  - Добавлены тестовые сценарии проверки отсечения правил с `$removeparam`, инвертированными модификаторами (`$~image`), скриптлетами (`#%#`), внедрением CSS (`#$#`) и URL-путями (`||reddit.com/ads/*`).

  - В `pollSyncStatus` и `openSyncProgressModal` добавлена проверка заголовка `Content-Type`: ответы, не являющиеся JSON (транзитные шлюзовые страницы прокси), корректно пропускаются или выводятся в виде читаемой ошибки без повреждения терминала.
  - Добавлена гарантированная публикация финального статуса в терминал окна прогресса (`[SUCCESS] Синхронизация списков успешно завершена!`) даже при кратковременных сетевых задержках WebSocket.

- **Улучшенная согласованность фаз разрешения и маршрутизации (`internal/engine/domain_resolver.go`, `internal/api/handler_reconfig.go`)**:
  - Экспортированы методы `SetStatusPhase` и `SetStatusIdle`: во время сверки интерфейсов статус динамически отображает этап «Сверка и синхронизация интерфейсов роутера...».
  - В `SyncAll` добавлен учет флага очистки `pendingPurge` для повторных конкурентных вызовов и корректный сброс статуса в `idle` при отмене контекста.

  - Модальное окно гарантированно доходит до финального экрана с зеленой плашкой успешного завершения и кнопкой «Закрыть».

## [1.0.178] - 2026-09-23 - Согласование и очистка маршрутов при изменении интерфейсов
- **Автоматическое согласование маршрутов при смене интерфейсов (`internal/routing/manager.go`)**:
  - Реализован метод `ReconcileInterfaces()` / `reconcileInterfacesLocked()`: при отключении интерфейсов в настройках сервис фильтрует все выученные и агрегированные маршруты в оперативной памяти `m.routes`, удаляя ссылки на отключенные интерфейсы.
  - IP-адреса маршрутов автоматически удаляются из ядерных `ipset` (`sr_<iface>`) исключенных интерфейсов, а сами наборы полностью сбрасываются (`FlushSet`).
  - Если для авто-маршрута не осталось ни одного активного интерфейса, маршрут удаляется из реестра. Для ручных и списочных маршрутов выполняется безопасная перепривязка к первичному активному интерфейсу.
- **Очистка устаревших статических маршрутов в KeeneticOS NDM (`internal/routing/keenetic_ndm.go`, `internal/routing/manager.go`)**:
  - В `buildActiveSRRoutesMap` добавлен строгий фильтр только по разрешенным интерфейсам (`GetAllRoutingInterfaces()`), благодаря чему статические маршруты отключенных интерфейсов (например, `OpkgTun0`) классифицируются как сироты (`is_orphan`).
  - `ReconcileInterfaces()` автоматически вызывает `PruneKeeneticOrphans()`, удаляя команды `ip route ... <disabled_iface>` из running-config KeeneticOS с сохранением конфигурации (`system configuration save`).
  - В функции предзагрузки `preloadKnownRoutesToIPSet` добавлен фильтр, запрещающий считывание и восстановление маршрутов неактивных интерфейсов из Keenetic NDM.
- **Мгновенное обновление таблиц маршрутов в Web UI (`internal/web/static/app.js`)**:
  - В функцию `saveInterfaces()` и в обработчик завершения фоновой синхронизации `pollSyncStatus()` добавлены вызовы `fetchRoutes()` и `fetchKeeneticRoutes(false)`: интерфейс теперь обновляет обе таблицы сразу после применения изменений.

## [1.0.177] - 2026-09-23 - Синхронный сброс статуса и устранение гонки отображения прогресса синхронизации
- **Устранение гонки состояний и ложного мгновенного завершения модального окна (`internal/engine/domain_resolver.go`, `internal/web/static/app.js`)**:
  - Добавлен метод `dr.ResetStatusStarting(msg)`: статус синхронизации моментально и синхронно переводится в активное состояние (`is_syncing: true, phase: "preparing"`), обнуляя счетчики и фиксируя новое время старта до запуска фоновых операций (`RoutingMgr.Start()`).
  - В `app.js` добавлен строгий фильтр устаревших данных (`st.started_at < state.syncModalOpenedAt - 500`): модальное окно полностью игнорирует результат предыдущей завершенной сессии и не переключается в статус «Готово» до получения актуальных данных нового процесса.
- **Новая фаза `preparing` и анимированный прогресс-бар (`internal/web/static/app.js`)**:
  - Шаг 1 «Списки» теперь отображается активным с первых миллисекунд (с анимированным шиммером `indeterminate`), пока роутер подготавливает интерфейсы и правила фаервола.
  - При переходе к DNS-резолвингу статус переключается в `resolving` (Шаг 1 завершен, Шаг 2 активен с реальным числовым счетчиком `X / Y`), затем в `applying` (Шаг 3 «Маршрутизация»), и только по фактическому завершению — в `completed` (все шаги завершены, 100%, кнопка «Закрыть»).
- **Синхронизация консоли процесса (`internal/web/static/app.js`)**:
  - Добавлен тег `CONFIG` в фильтр логов терминала модального окна: системные события реконфигурации роутера теперь сразу отображаются в терминале модального окна без задержки.

## [1.0.176] - 2026-09-23 - Унифицированная реконфигурация и очистка авто-обходов после прогрева
- **Единый универсальный пайплайн реконфигурации (`internal/api/handler_reconfig.go`)**:
  - Создан единый метод `TriggerUnifiedFullReconfiguration`, синхронизирующий логику при сохранении списков ресурсов (`SaveDomainLists`, `SyncDomainLists`) и сетевых интерфейсов (`UpdateConfig`, `SaveInterfaces`).
  - Гарантирует одинаковую последовательность: актуализация интерфейсов в `RoutingMgr.Start()`, сброс кэшей сессий Conntrack Watcher и запуск прогрева с очисткой устаревших авто-маршрутов.
- **Очистка предыдущих авто-обходов после завершения прогрева (`internal/routing/manager.go`)**:
  - В метод `CommitWarmUpBatch` добавлена процедура `purgeAutoRoutesLocked`, удаляющая из оперативной памяти все динамические авто-маршруты (`isAutoRoute`), реликтовые NDM-записи `(NDM)` и маршруты отключенных списков.
  - Сохраняются только маршруты активных (включенных) списков и истинно ручные маршруты.
  - В Keenetic NDM передается пакет только с актуальными маршрутами: `BatchAddRoutes` автоматически отправляет `no ip route ...` для всех устаревших авто-обходов, оставляя в роутере исключительно маршруты включенных списков (например, `AI Services`).
  - Ядерные наборы `sr_<iface>` в `ipset` очищаются и заполняются заново только актуальными адресами.
- **Сохранение накопительного журнала доменов Auto**:
  - Список «Автоматические обходы (Auto)» в `config.json` сохраняется и не сбрасывается, работая как накопительный журнал, и резолвится только при явном включении пользователем (`enabled: true`).

  - Устранено зависание обработчиков API (`/api/domain-lists`, `/api/status`), вызванное ожиданием чтения `m.mu.RLock()`.
- **Автоматическое модульное тестирование**:
  - Добавлен тест `TestManagerStartNoDeadlock` для проверки корректного запуска без зависания мьютексов.
