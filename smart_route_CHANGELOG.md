All notable changes to the SmartRoute project will be documented in this file.

## [1.0.128] - 2026-09-18 - Защита KeenDNS / Keenetic Cloud и ограничение перехвата iptables
- **Защита доменов KeenDNS и облачных ретрансляторов Keenetic Cloud** (`internal/config/config.go`, `internal/routing/manager.go`, `internal/routing/keenetic_ndm.go`, `internal/engine/proxy.go`, `internal/engine/udp_proxy.go`, `internal/api/handler.go`):
  - Реализован механизм абсолютного системного иммунитета `IsKeeneticCloudTarget`: домены Keenetic (`*.keenetic.link`, `*.keenetic.pro`, `*.keenetic.name`, `*.keenetic.io`, `*.keenetic.com`, `*.keenetic.ru`, `*.keenetic.net`, `*.netcraze.link`, `*.netcraze.pro`, `*.netcraze.io`, `*.netcraze.cloud`, `*.omni.ru`, `*.knt9.xyz`) и официальные IP-адреса серверов-ретрансляторов (`31.135.14.238`, `178.250.154.58`, `95.213.212.50`, `185.162.93.96`, `87.228.71.67`, `5.35.2.42`, а также локальный интерфейс `ezcfg0` `198.51.100.11`) защищены от перехвата и перенаправления.
  - Метод `FindBestRuleMatch` присваивает облачным целям наивысший приоритет исключения (score 999999), гарантируя прямую маршрутизацию через основной провайдерский шлюз (WAN) без отправки в VPN-туннели.
  - В `Manager.AddMultiRoute`, `NDM.AddRoute`, `NDM.BatchAddRoutes` и обработчике `autoEntries` заблокировано добавление маршрутов для целей Keenetic Cloud.
  - В `CleanKeeneticCloudRoutes()` и `PurgeTargetRoutes()` реализована автоматическая очистка любых статических маршрутов `/32` к серверам Keenetic Cloud при старте службы.
- **Ограничение перехвата входящего трафика в iptables PREROUTING** (`internal/routing/iptables.go`, `internal/config/config.go`):
  - Правила NAT `REDIRECT --to-ports 10880` теперь строго ограничены локальными интерфейсами (`-i br+` по умолчанию из `cfg.GetInterceptInterfaces()`), исключая перехват входящих внешних соединений с WAN (`eth3`, `ppp0`, внешних белых IP и прямого доступа KeenDNS Direct).
  - В цепочки `SMART_ROUTE_PREROUTING` и `SMART_ROUTE_MANGLE` добавлен безусловный `-j RETURN` для всех IP-адресов облачных релеев Keenetic Cloud и локального интерфейса `ezcfg0` (`198.51.100.11`).

## [1.0.122] - 2026-09-18 - Устранение 30-секундного таймаута (ERR_CONNECTION_TIMED_OUT) при блокировке HTTPS и мгновенный TCP RST
- **Устранение таймаута при блокировке HTTPS** (`internal/blocking/manager_linux.go`):
  - Удален неселективный сброс `DROP` в таблице `mangle PREROUTING`, из-за которого браузер ожидал ответа 30 секунд и завершался ошибкой `ERR_CONNECTION_TIMED_OUT`.
  - В цепочку `nat PREROUTING` добавлено правило `ACCEPT` для заблокированных IP, предотвращающее их перехват прозрачным прокси `10880` (`SMART_ROUTE_PREROUTING`).
  - В цепочке `filter FORWARD` для всего TCP-трафика на заблокированные адреса (включая HTTPS 443) активирован мгновенный аппаратный сброс `REJECT --reject-with tcp-reset`, передающий сигнал TCP RST клиенту за доли миллисекунды.
  - Сохранена работа страницы-заглушки и редиректа при обращении по незащищенному протоколу HTTP (порт 80).

## [1.0.116] - 2026-09-17 - Дедупликация и последовательная проверка аплинков DNS с отображением доменных зон
- **Оптимизация тестирования аплинков DNS в Web UI** (`internal/web/static/app.js`):

  - **«Не перехватывать и порт 530»** (`standalone`): Автономный режим DNS. Служба слушает порт 530, правила перехвата не создаются, системный DNS KeeneticOS не изменяется (`no opkg dns-override`). DNS используется внутренним резолвером SmartRoute и клиентами при явном обращении на порт 530.
  - **«Включить dns-override и порт 53»** (`dns_override`): Штатный нативный режим KeeneticOS. Служба автоматически слушает стандартный порт 53 и через NDM CLI активирует `opkg dns-override`, освобождая порт 53 от встроенного `ndnproxy`. Все клиенты локальной сети и сам роутер работают через DNS SmartRoute напрямую на максимальной скорости ядра без правил iptables. При остановке службы `dns-override` автоматически отключается.
  - **«Прозрачный перехват через iptables (DNS Hijack 53 → 530)»** (`iptables_hijack`): Служба слушает порт 530, а ядро Linux Netfilter автоматически перенаправляет все DNS-запросы клиентов (`-i br+ -p udp/tcp --dport 53 -j REDIRECT --to-ports 530`).
  - Механизм самовосстановления (Self-healing Guardian `EnsureHooks`) отслеживает и автоматически восстанавливает правила перехвата DNS при пересоздании мостов или сбросе цепочек Netfilter.
  - Интерактивный блок выбора режима в веб-интерфейсе DNS с автоматической корректировкой входящего порта и подсказок.
